ls：可以列出一个文件夹里所有的文件和文件夹。

git init：把当前文件夹初始化为 Git 仓库。

git commit：把文件正式保存为一个版本，并附上说明。

git push：把本地的代码推送到 GitHub 上。

在ai开始给个人网站写代码是背景有报错过，经过追问发现是代码迭代了（bgcolor用background-color）

代码思路1：评分函数上将空格数量设置最高分，为下一步提供了最大的滑动空间

代码思路2：新数字概率上不同，比如“2”设置1000频率，那“16”设置为2频率

小游戏2048网址：https://diezxii.github.io/2048game/

初始：【我要制作一个2048游戏，方格规模为4*4，初始随机位点生成方块“2”，两个“2”相碰为“4”，两“4‘相碰为”8“，依次类推到2048，游戏截至。每滑动一次生成一个新数字方块，数字不超过最大数字（比如合成到8，可以生成2，4，8，不能生成大于8的数），且新生成的方块上线为32，不要有撤回功能游戏能。能直接上手玩，浏览器即可打开（用github），有阶梯式得分，先生成大概代码】，想要试一试ai对这个传统游戏是否足够了解，方便进一步优化（往生成概率，上线和积分发展），结果ai确实已经能七七八八完成，但是记分太僵硬，生成想16 32这样的大数概率很高。

第一次迭代：【新生成数字上线改为16，同时把生成2，4，8，16的概率依次递减，也就是说基本多生成2，4，8。16几乎不生成。记分再细化一下，着重注意连合成，合成数值大小，还有把不同数值的方块色差拉大】，想细化记分规则和生成概率，同时优化了画面，结果还算达到预期，记分和生成上已经完成，但是画面不够舒服，于是开始在画面和互动上调整

第二次迭代：【游戏色调分暖色和深色模式，，显示玩家一共游玩局数，同时局数，最高分可以重置，玩家点了后要提醒再确认。滑动效果更丝滑，连击效果更明显，搞个本地排行榜】，想要让操作更流畅，画面更好看，同时增加重置互动，ai基本完成

第三次迭代：【你来玩到2048，可不可以自动演示】，想调动ai完成2048，游戏加入自动演示效果，但是ai玩到2024就停止了，演示时无法暂停，而且说要是胜利（到达2048）就不计入排名，便开始更改

第四次迭代：【胜利的的得分也纳入排行榜，演示速度可以选择快进，演示时要是点停止可以回档也可以继续，调整一下这些点击方块的位置，好看一些。】开始调整ai自主完成功能，演示功能完善了不少。但是发现快进后悔卡帧

第五次迭代：【我发现如果自动演示x4，x8下方块移动会对不上框框，会错位啊，自动演示开始后回档没有问题，另一个选择是继续自动演示，不然会卡帧，直接不要接着玩这盘了】，想要视觉效果更好，ai基本完成任务，经过几次试验，完成本小游戏任务。

第一段通过前两次迭代完成，检验方式是个人用电脑和手机端进行试验，无误

第二段通过3~5迭代完成，通过直接在游戏里设置ai自动演示检验ai可以完成2048，无误
